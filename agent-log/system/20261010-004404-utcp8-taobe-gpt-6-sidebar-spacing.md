# 侧栏纵向间距与 M3 对照

- 用户原始请求：「纵向 padding 不均匀，看看 m3 的标准是现实怎么样」。
- 分支/基准：codex/standalone-ts，887bce84d8。保留其他任务已有改动。
- 官方依据：AndroidX Material 3 NavigationDrawerTokens 的 ActiveIndicatorHeight 为56dp、IconSize为24dp；NavigationDrawerItem使用最小行高及垂直居中，默认ItemPadding只定义左右12dp。未把旧M1列表说明或第三方Expressive实现作为标准M3依据。
- 实际原因：原Dashboard行32px、下方18px；账号行30px、组尾14px；两种中心距分别49px和44px，与用户截图的不均匀节奏对应。账号行原上下6px padding本身对称，差异来自行高和组间留白组合。
- 实现：保留既有32px紧凑图标框，账号行也统一32px、垂直居中，名称和数量共用16px行高。开关、Dashboard和账号分组的间距使用同一8px变量；相邻账号组使用间距，最后一组没有额外尾部margin。仓库子行、56px收起栏及账号/选择/折叠模型不改。
- 版本：并行任务已从0.11.1升至0.11.2；本任务执行patch递增后权威版本为0.11.3，package.json与package-lock.json一致。
- 验证：类型检查通过。实际4173浏览器CSSOM已加载新账号规则，开关及Dashboard均32px、二者边缘距离8px、Dashboard到账号列表margin为8px。当前主预览0账号，不能据此声称真实两账号完整目视通过。只同步已有样式断言，没有新增或运行自动化测试。
- 原生窗口仍是此前0.11.0签名包，未打包或替换原生应用。用户本轮提出局部样式与标准对照，按仓库当前打包规则不从此前授权流程的打包推定本轮新的打包权限。未重启4173/4174、改写凭据、提交或推送。
- 本项目32px/8px为紧凑桌面适配；M3标准56dp行高与当前实现的尺寸清楚区分。
- 收尾：0.11.3类型检查、生产构建与差异格式检查通过。仅核对预览已加载样式，未将空账号预览称为截图中真实两账号布局的目视验收。
