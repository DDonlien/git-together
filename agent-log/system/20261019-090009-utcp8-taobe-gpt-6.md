## 诊断与决定

- 当前 matchAccountRepositories 直接将所选父路径传给 addRepositories，完全没有递归发现，也没有按 accountId 限定目标。这直接解释截图中的原版错误。
- 原版 addRepositories 负责验证、保存及初始化远端，selectRepository/refreshRepository 与原版后台负责后续读取；保留这些实现，在 UI 适配边界补回有限的文件夹发现。
- 当前 catalog 仅从原版内存缓存的单个 remote 推导 Gitea 关联；尚未刷新的已保存仓库可能退回本地分组。将用原版只读 getRemotes 重建身份，缓存随原版 remote 更新失效，不另存第二份关联。
