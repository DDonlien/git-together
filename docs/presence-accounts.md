# Presence 账号与自动管理

在 GitTogether「设置 → 插件 → Presence」启用开关，登录账号归属服务的邮箱和密码。账号网页位于服务基址的 `account`；当前入口为 [账号注册与登录](https://git.freshli4.com:10443/presence/account)。注册与修改密码接受8至128个字符，无字符组合要求；邮箱尚未验证，尚未提供邮件找回。密码修改只在账号归属服务网页处理。

一个 GitTogether 实例绑定一个 Presence 账号，自动登记设备，并将当前 Git 账号有权访问的全部仓库登记到个人范围；已关联的本机工作区自动公布。无需选择个人仓库、登记密钥或团队。不同设备的清单按设备分别保存，移除一个设备中的仓库不会覆盖其他设备。未关联工作目录的仓库可读取授权协作状态，远端操作只作用于目标已关联且仍可访问的工作区。

项目详情中可向同账号其他设备请求 Commit、Submit、中止操作或丢弃更改。保留现有分支预览、可编辑说明、文件选择及丢弃备份；Submit 为逐分支生成说明 → Commit → Push。Git 凭证和文件正文留在执行设备，Presence 传递有限操作及状态。账号会话30天到期后，已登记设备可继续用独立设备凭证；撤销、改密码及身份不可验证会阻止接收/认领。

## 连接多台 Presence 服务器

账号有唯一归属登录服务。其他服务器必须由安装者明确配置 `accounts.trustedIssuers`，才能验证该服务的 Ed25519 签名；身份由 canonical issuer 和 subject 确定，邮箱相同不会合并账号。App 添加服务器只输入 HTTPS 地址（开发可用 loopback HTTP），用当前账号取得目标限定、120秒有效且一次使用的身份证明；归属服务的密码和登录会话不会转发给目标。

每台服务器单独签发会话和设备凭证，独立维护组织、状态和命令。网页 `identity/signin` 可从受信任的归属服务登录：先在归属服务确认目标，再以表单交付短时凭证，目标使用 HttpOnly Cookie。设备后续通过单用途签名委托检查归属授权代次；委托只能查询授权有效性，不能登录或登记设备。目标定期重新验证，控制请求/认领及组织变更另行验证；归属服务不可达时暂停授权，不猜测权限。数据卷的 `identity-private.pem` 必须连同数据库备份，避免重装后无法验证既有设备。

服务器地址列表可选择、停用和移除。关闭 Presence 后只保留开关，停止对应连接和控制。重新登录同一账号保留设备关联并更新所选服务器的身份；需要另一账号时先退出当前账号，或从应用菜单“打开另一个实例”使用独立账号数据目录。也可显式使用 `--presence-instance=<小写名称>` 启动更多独立实例；默认实例的数据保持原位置。独立实例不会共享用户账号、Git凭证或远端执行记录。

## 托管组织

Presence 组织独立于 GitHub/Gitea 组织。组织所有者在 [组织管理](https://git.freshli4.com:10443/presence/manage) 创建组织、生成24小时一次使用的成员邀请链接、维护角色和具体仓库网址。成员登录后接受邀请；同账号可参加多个组织。邀请和角色不按邮箱、Git 平台组织或仓库管理员权限自动生成。

绑定仓库要求当前个人身份同时拥有 Presence 组织和该 Git 仓库。网页先确认 Git 身份，服务器重新读取仓库及所有权：个人仓库要求实际 owner 身份；GitHub/GitHub 企业版的组织仓库要求 active 的组织 owner，Gitea 要求 `is_owner`。单纯可读、可写或仓库 admin 不够。Git 验证令牌仅保留在内存30分钟，不写数据库、日志或广播；GitHub 可用设备授权，Gitea/企业版使用访问令牌。额外 Git 服务域名需安装者配置 `gitProviders.hosts`，默认允许 GitHub 与 Presence 所在域名的 Gitea。纳管目前提供这三种平台的所有权验证入口。

用户是组织成员且当前 Git 账号可访问匹配仓库时，自动使用对应组织范围，仓库图标、Dashboard“托管组织”列/筛选和详情展示组织及个人角色。同一仓库可分别绑定多个组织或服务器，既不禁止也不合并；每个范围独立处理人员、设备、预览及命令。跨用户控制要求同一纳管组织、角色严格高于目标，目标执行仍受实际 Git 权限约束。组织修订变化使旧预览、重试、认领失效。

## 发行与验收

客户端0.30.0源码与GitPresence0.6.0分别维护。类型、Rust编译、生产构建、容器部署与真实账号/双设备操作是不同证据；本轮不代注册、授权真实 Git 账号或执行实际仓库写操作，也不把源码更新称为已安装应用更新。官网个人 Docker 下载、组织计费、邮箱验证/找回及开源许可证仍独立交付。
