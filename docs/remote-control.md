# 远端控制

此功能从已授权的 Presence 账号登记设备，再由目标设备的 Rust 后台执行 Git。账号、设备、项目及 worktree 是分别验证的身份。首轮沿用 Presence 访问授权，不发送 GitHub/Gitea 的 Git 凭证到服务器；平台网页登录 Presence 尚未实现。

## 开始使用

1. 两台设备连接同一个 Presence 服务，并使用属于同一个用户的访问授权。
2. 在“设置 → 插件 → Presence → 远端控制”填写设备名称，登记此设备。只读访问密钥没有登记权限，需要管理员提供同账号的登记密钥；本机已配置私有登记授权时可留空。
3. 在目标设备勾选“允许控制的本机项目”。默认没有任何项目开放；无需关联源设备的本机文件夹，目标项目须有已关联的真实工作目录。
4. 在项目页展开 Presence，找到另一台设备的工作目录，使用 Commit、Submit、中止操作或丢弃更改。

设备签发独立凭证并使用系统加密保存。设备登记密钥与旧只读密钥分别授权；“我的设备”可撤销单台设备。更换 Presence 账号或服务器需要重新登记，不向新服务器发送旧设备凭证。

## 四种行为

- Commit：目标为当前分支生成可编辑的 Summary/Description，你确认文件清单后，在目标端创建本地提交。
- Submit：相同的分支草稿和清单确认后，在目标端 Commit → Push。推送未确认时保留已有提交；“重试推送”只推送该提交，目标 HEAD 变化会停止。
- 中止操作：只取消预览时看到的具体任务。已开始的 Git 提交安全收尾，停止可取消部分；进行中的 merge/rebase 使用实际 Git abort。游离 HEAD 的变基工作区保留中止入口。
- 丢弃更改：将选中文件恢复到目标当前 HEAD，并删除选中的新增文件；原文件和原暂存状态先备份。不会改写提交历史或自动删除忽略文件。结果中的“恢复更改”仅在目录没有新变化时恢复。

仅处理落盘文件。Presence 已观察到选中文件的编辑器未保存或失联状态时，写操作会停止；未接入编辑器时无法收集内存中的修改。

## 后台与结果

启用远控后，关闭窗口会隐藏到托盘，Rust 执行器继续运行；“打开 GitTogether”恢复窗口，“退出 GitTogether”断开。没有安装开机服务。睡眠、关机或离线时无法接受新操作。

命令有唯一编号和有效期，绑定目标设备、工作目录和预览时状态。服务器保存请求与结果，目标加密保存执行记录。进程在事务中退出后，重新连接报告中断或已保存的提交结果，不自动重做未知的 Git 写入。预览超过十分钟或目标文件/分支变化时需重新确认。

## 团队范围

管理员在服务器登记团队成员角色与明确纳管的项目 ID；目标设备再将具体项目选择为这个团队。Owner/Admin/Member 的角色必须严格高于目标成员，操作还须在目标公布的动作集合内。团队控制不能访问未纳管项目或任意文件夹；同账号的个人控制仍须目标设备勾选开放。

## 当前交付边界

源码包含有限 HTTPS 命令、独立设备登记、Rust 执行、确认弹窗、备份恢复、托盘及单实例保护。类型/编译和构建不代表真实双设备 Git 写入验收；正式安装包另受 macOS 与 Windows x86/x64 同次发布规则约束。
