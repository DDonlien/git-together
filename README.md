# GitTogether

<img src="assets/brand/gittogether-app.png" width="96" height="96" alt="GitTogether 图标" />

把仓库当作项目，把分支当作任务。

品牌图标原图位于[assets/brand](assets/brand/README.md)，包含选定的应用图标、正方形版本和透明图形。在`macos/`执行`npm run icons`可重新生成macOS、Windows与网页图标。

GitTogether 是一款面向 macOS 和 Windows 的独立 Git 工作台，把 GitHub（含企业版）、GitLab、Gitee、Gitea 和本地 Git 目录放在同一个视野里。它为同时推进多个项目、多个分支的开发者而设计：从仓库总览找到项目，在项目内看清分支、提交和文件，再按需接入本地更改。

[0.30.11](https://github.com/DDonlien/git-together/releases/tag/v0.30.11)已正式发布macOS ARM与Windows x86/x64，协作人员姓名后以括号显示实际登记设备名，并包含此前的GitHub自动续期与Gitea分支参与判断修复。旧版本没有保存GitHub续期凭据时，升级后的既有登录可能需要正常授权一次；新的登录会自动续期，账号及本地关联保留。安装包及公共更新源已核验，用户自行选择安装和重启。

## 一个项目，多条任务线

GitTogether 的核心视角是：仓库是项目，分支与 worktree（同一仓库的独立工作目录）是项目里的任务上下文。不同工作线围绕同一个仓库组织；浏览另一个分支，不等于检出它，也不会改动你正在工作的目录。

## 你可以用它做什么

### 汇集不同账号下的仓库

连接 GitHub 或自托管 Gitea，让可访问的仓库进入同一份 Dashboard。按账号、组织、仓库类型、本地关联状态和公开/私有可见性进行多选筛选，快速找到需要关注的项目；点击仓库的文件夹图标，即可展开实际远端分支。

侧边栏和Dashboard仓库行右侧提供置顶图钉：悬停或键盘聚焦时显示，点击后优先排列，再次点击取消。两处共享本机保存的置顶状态，已置顶图钉常显。

### 不克隆，也能了解远端

没有本地目录，也可以浏览远端分支、提交关系和文件树。仓库工作台把分支图、更改与 Diff（文件差异）、文件树并排放置：选择一次提交，查看它改了哪些文件，同时在当前目录结构中辨认这些变化。

分支图顶部可按分支和提交者分别多选筛选，快速查看当前已读取范围内某几位成员的提交记录。

点击仓库标题下的网址，即可用系统默认浏览器打开对应的 GitHub 或 Gitea 仓库；也可用键盘聚焦后按 Enter 打开。

三栏之间的分隔条可左右拖动，以10%为一档调整空间，也支持键盘方向键。各栏仍可独立收起；重新展开会恢复当前工作台里调整过的比例。

远端内容通过平台API读取，与后台Git Fetch同时进行；已读取的分支和提交先显示，Fetch变慢或失败仍保留远端内容，并单独提示本地引用更新状态。

### 接入已有的本地工作

在桌面版中选择已有 Git 目录或项目父目录，自动匹配其中属于该仓库的真实工作目录。每个分支可以单独关联、解除；仓库入口保留「尚未关联 / 部分关联 / 完全关联」，未检出的分支不会自动创建目录。各 worktree 的未提交更改和本地文件树独立读取。选择本地历史提交，可查看完整更改列表、文件状态和提交正文；取消后恢复工作区文件选择与提交草稿。更改列表不显示文件内容预览。远端文件可打开平台网页，本地文件可用系统默认应用打开。文件树底部显示分支和当前树提交号；本地目录紧随分支，点击可在系统文件浏览器中打开。

已有本地仓库默认使用系统 Git/SSH，沿用原来的远端地址、凭据助手、SSH 密钥与 agent。需要使用应用登录的账号时，在「设置 → 账号 → 仓库授权与本地认证」中为该仓库选择「应用账号」。首次下载未关联分支使用应用账号，之后沿用该仓库已保存的认证方式；失败时不会自动切换账号。

账号设置会显示应用的仓库授权、读取和基础写权限，并列出未授权、无写权限、尚未确认及检查错误。GitHub App 需要安装到对应仓库且拥有 Contents 写权限，用户本身也需有写权限。系统认证可能使用另一账号，应用权限提示不代表系统 Git 的权限；受保护分支和 GitHub Actions 工作流还可能有额外限制。这些改动目前通过源码编译与构建检查，尚未随正式安装包交付。

### 让信息有序，给工作留出空间

Material 3 的亮暗主题与清晰的信息分区，让工作台保持统一：侧栏融入背景，内容卡片用色调区分层级。侧栏和三个内容栏都可以独立收起；调整布局时，当前选择、目录展开和任务草稿保持不变。

### 接入团队协作状态

0.23.0 源码在「设置 → 插件 → Presence」连接自托管服务器，查看团队在线工作区、分支、Git 修改和编辑器未保存状态。仓库图标显示实际协作连接，工作台的 Presence 可展开查看文件；失联时保留上次记录并明确显示未知。首个 NAS 服务已部署，初次只开放 GitTogether 和 GitPresence 两个仓库。源码与网页预览已连通，桌面已随0.27.1在macOS和Windows x86/x64正式交付，详见 [Presence 使用说明](docs/presence.md)。

当前源码的协作弹窗按设备分别显示：同一账号的两台设备各占一行，显示各自的设备名、工作状态和远程操作；仓库入口展示该设备操作的分支，分支入口仅展示对应分支，标题按设备数统计。

GitHub企业版支持自定义域名（如`github.dxc.com`），GitLab支持官方与自建服务，Gitee使用v5接口。账号可以使用访问令牌连接，也可在「网页授权应用配置」中填写该平台及域名登记的OAuth应用，之后通过系统浏览器完成登录和企业SSO。GitLab公共客户端使用PKCE，无需Client Secret；企业GitHub与Gitee需要该域名的应用密钥。应用配置按域名在本机加密保存，切换域名不会复用其他服务的凭据；未获SSO批准时明确提示并保留上次仓库数据。

## 从哪里开始

1. 在设置中连接 GitHub 或 Gitea 账号。
2. 在 Dashboard 搜索仓库，展开分支，或点击仓库名称进入工作台。
3. 浏览远端提交和文件；需要查看本地更改时，再在桌面版关联已有目录。
4. 本地未提交更改填写Summary即可Commit，Description选填；Submit沿用这份草稿，审阅文件清单后提交并推送。也可以使用AI生成可编辑说明，生成失败仍可手工填写Summary后Submit；Commit后可单独Push选中的提交。

仓库的可见范围始终取决于账号授权与平台权限。关联本地是可选步骤，不是读取远端内容的前提。

Dashboard可点击「状态」表头按仓库读取/Git状态排序，再次点击反向；未确认的仓库与已确认同步的仓库分开排列。

此前0.22.5已完成的迁移读取修正随0.22.6公开交付：失效的旧目录不会阻止重新关联，无法读取的目录会显示错误；本地连续保存或暂存仍自动刷新。更新本地远端引用失败时，远端提交仍继续读取并明确显示反馈。残缺文件树允许重新读取，Gitea中文文件的提交Diff可正确显示，多个同时等待的获取请求可以分别取消。0.22.6安装ZIP及Tauri更新包已完成签名、公证及公共更新源核验。

遇到读取或更新异常时，可在「设置 → 日志 → 打开日志文件夹」找到本机记录，也可复制日志文件到剪贴板。日志自动保留最近 24 小时，不上传，不记录令牌、密码、文件内容或明文仓库路径；空间上限 128 MB，超出后较早记录会被清理。此功能从 0.13.0 起提供，已有安装版需更新到包含此功能的版本。

## 当前状态

源码新增提交菜单的三组操作：标准 Git、Git Together 非 AI、AI。AI「同步到最新」可选择并记住来源分支，在隔离目录合并和处理文本冲突；最后审阅文件 Diff、编辑 Summary/Description，一次确认创建本地合并提交。二进制、LFS、链接和子模块冲突会停止并提示人工处理；新功能尚未打包，源码检查不代表真实 AI/Git 运行验收。

性能记录已接入源码：Dashboard输入等待、帧间隔、渲染、响应读取/校验、并行请求、Git排队及日志写入压力分别记录在现有本地日志中。日志聚合并后台批量写入，不逐帧写磁盘；详见[性能日志说明](docs/performance-logs.md)。已安装App需更新到包含此功能的版本，源码验证不表示实际卡顿已解决。
0.30.1源码统一了Commit和Submit的说明要求，Summary必填、Description选填；修正Submit弹窗横向裁切，Git失败也会区分磁盘不足与具体LFS故障。Windows候选包已通过[构建与安装验证](https://github.com/DDonlien/git-together/actions/runs/38285723988)，正式自动更新尚未发布。

0.22.10修正更新包附带macOS元数据导致解压失败的问题。更新检查、下载、安装记录真实失败类别、脱敏错误链及系统错误码；界面区分更新包、签名、网络、磁盘和实际访问限制，失败继续保留下载及安装重试。旧版已下载失败包时，退出并重新打开应用，再检查并下载0.22.10。

0.22.9取消更新前的通用后台等待：确认重启后立即安装，自动检查会暂停；安装状态集中在更新卡片，失败保留下载内容并提供直接重试。

0.22.7修正从Finder启动时Git没有继承系统代理的问题，沿用已配置的macOS代理及绕过规则，同时保留仓库自己的代理设置。读取日志增加真实Git失败类别、退出码和部分任务失败信息，通用Git错误不再归为账号权限失效。同样环境的公开仓库读取及隔离实际fetch、取消/恢复已验证，安装包和公共更新源完成核验；没有将这些证据扩大为逐私有账号或安装版运行验收。

0.29.2已在[GitHub Releases](https://github.com/DDonlien/git-together/releases/tag/v0.29.2)正式公开，同一main历史提交36179f0b60提供macOS Apple Silicon、Windows x86/x64安装包。修复GitHub本机授权把系统拒绝端口误报为占用的问题；回调不可用时自动使用GitHub官方网页验证码授权，支持复制、轮询、取消与重试。自有GitHub App的设备授权已一次启用；公证、更新签名及完整公开下载/清单回读通过。用户可在设置检查更新，自己的GitHub登录/同意由用户完成。

0.22.11已公证并在[GitHub Releases](https://github.com/DDonlien/git-together/releases/tag/v0.22.11)公开。安装ZIP与Tauri更新包完成公共下载摘要回读、验签及解压后版本、签名、公证票据核对，ZIP约4.6MB。推送改为分支与仓库图标的上传动画和短暂成功勾，区分全部/部分本地目录；弹窗与详情提供细进度条。Commit/Submit支持Tracked/Untracked分组与多选，真实提交和AI只处理选中范围，保留未选暂存内容。桌面采用Tauri 2和Rust后台，生产包只包含原生程序及React资源；Git通过本机Git/Git LFS执行，保留钩子和签名配置。


当前源码支持真实远端与多个已关联worktree的浏览，以及Commit / Submit / Push、Pull / Get Latest / Clean。Dashboard行内和仓库顶部统一为Pull / Get Latest、Commit / Submit、Push、Clean和隐藏五组；移除Reconcile及手动Fetch，图标使用手形指针，同组只显示一个正数角标。Dashboard数量表头居中对应按钮组；仓库行覆盖筛选出来的分支/目录，收起不缩小范围；仓库页顶部覆盖当前分支筛选，中栏只处理选中的更改上下文。Commit只创建本地提交；Submit沿用本机Codex CLI登录，使用该CLI推荐的模型，为每个分支预填可编辑的Summary和Description，确认后Commit再Push。关闭重开或筛选保留各分支草稿，生成不覆盖手工修改；Push失败保留Commit，重试不重复提交。Summary和Description使用官方Material Web描边字段，空态及正文按紧凑桌面统一为13px；顶部搜索按M3 Search bar规范组合。

Pull只快进合入，未提交文件或分叉历史会停止。Clean先展示按远端恢复、补齐和删除的具体文件（包含忽略的本地文件），确认后执行，保留本地提交和暂存区。Get Latest核验最新文件及LFS后替换为深度1的新目录，并实际删除可独立回收的旧历史与缓存；未推送提交、其他分支、标签或共享主目录会阻止清理，独立分支worktree可整理成单层目录，其他目录需要的共享历史保留并如实报告。后台每5分钟及变化触发实际Git fetch，不合并或改工作文件；保留已有数量、检查反馈、离线暂停及失败退避。未关联分支继续通过下载入口创建并关联目录。在线协作仍在开发中。

源码与后续更新包以`main`为基线，公开安装版在[GitHub Releases](https://github.com/DDonlien/git-together/releases)提供。桌面打包入口自动完成检查、签名、公证和正式更新发布；只推送源码不会发布安装包。已打包的桌面版提供「设置 → 应用更新」，检查、下载和重启安装。更新沿用账号及本地目录配置，不修改仓库文件。确认安装后会暂停自动读取并立即安装；实际前台操作或授权未完成、安装失败时保留下载包，直接重试安装。浏览器预览与桌面版的授权、目录选择支持有所不同，具体限制见[运行说明](docs/development.md)。

[0.27.1联合发行版](https://github.com/DDonlien/git-together/releases/tag/v0.27.1)已公开提供macOS、Windows x86和Windows x64安装包，并完成公开下载与更新源核验。

Windows 提供明确标识 `Windows-x86` 和 `Windows-x64` 的当前用户 NSIS 安装包，包含 WebView2 引导程序，Git/Git LFS 沿用本机安装。两个目标已在 Windows 原生环境验证编译、加密存储、Git 选择范围提交和暂存保留、进程取消，以及实际安装、界面启动和卸载。账号保存在当前用户 LocalAppData 中，以系统 DPAPI 加密并限制访问。更新包使用应用内置公钥验签；Windows 安装器当前未配置 Authenticode 代码签名。可选 AI 提交说明使用已登录的本机 Codex CLI，官方 Windows CLI 支持 x64/ARM64，纯32位系统暂不提供该 AI 功能。

发布入口会收集同一 `main` 提交和版本的 macOS、Windows x86/x64 包，验证两个 Windows 原生构建报告并在发布机签署更新包；三个平台一并写入 `latest.json`、上传到同一 Release，再回读公开文件。任一目标失败会停止正式发布，不会退化为只发 macOS。Windows 双架构工作流见 [.github/workflows/windows-package.yml](.github/workflows/windows-package.yml)。

## 本地试用

列表行尾的隐藏图标可以隐藏仓库或分支；点击列表上方「已隐藏」可显示并逐项恢复，选择保存在本机。隐藏分支不参与「完全关联」判断，隐藏仓库不计入顶部仓库统计；所有本地分支都隐藏后，该仓库按未关联统计。查看隐藏项目时仍保持这些判断，恢复后重新计入；已保存的目录关联与文件保持不变。「设置 → 仓库行为 → 未找到我的提交」可选择默认或隐藏；按该仓库当前登录账号及已验证邮箱匹配作者，Gitea还核对当前账号实际推送了本分支提交的记录，完整读取后没有匹配才默认隐藏。Git邮箱与账号邮箱不同也可通过真实推送记录确认参与。导入仓库的原作者没有Gitea账号属于正常情况；未找到明确参与证据且身份、推送或历史读取不完整时保留显示并说明原因。自己创建或导入仓库的唯一分支继续保留，Gitea单独核对实际创建活动，创建身份未确认时也保留唯一分支。逐项恢复优先于默认隐藏，手动隐藏仍生效。

尚未关联工作目录的分支只显示「下载」和「隐藏」。在桌面版点击下载，选择存放位置和新文件夹名称，完成后会自动关联真实worktree；已关联分支恢复原有Git操作。初次下载仅获取该分支最新一层；若有LFS文件，需要已安装Git LFS。已有同名文件夹不会被覆盖。

在macOS上准备Node.js 22或以上、npm、Rust 1.90或以上、Xcode Command Line Tools和Git；处理LFS仓库还需要Git LFS。浏览器开发运行：

```bash
cd macos
npm install
npm run dev
```

浏览器预览位于[127.0.0.1:4173](http://127.0.0.1:4173/)，开发入口同时启动Rust服务。开发桌面窗口时，在`macos/`运行`npm run desktop`，它自动启动自己的界面服务；这两个入口共用4173，选择一个运行。开发账号使用独立会话，应用更新仅在正式安装包中启用。

GitHub 网页授权的首次开发配置、桌面打包与验证命令见[运行说明](docs/development.md)；应用配置由开发者准备，不是每位使用者的登录步骤。桌面重新授权通过系统浏览器完成，复用应用安全存储；旧独立授权配置首次升级时自动安全迁移。

Summary与Description在中栏和提交弹窗中使用官方Material Web描边文本框，保留浮动标签和官方焦点样式。顶部搜索由官方填充字段与图标按钮按M3 Search bar规范组合，采用36px紧凑高度与13px文字，顶部默认宽300px；支持即时筛选、清空和Cmd/Ctrl+K。Material Web尚未提供独立Search bar组件。短窗口中提交字段独立滚动，底部操作保持可见。

Commit/Submit弹窗按Tracked/Untracked分组，可通过文件、分组或全选复选框调整真实提交范围；新增、修改、删除分别标色，删除路径加删除线。AI只读取选中范围，原有未选暂存内容保持。推送时分支显示上传动画，完成显示双勾约2.6秒后消失；仓库全部目录推送用实心箭头/双勾，部分用虚线箭头/单勾，Dashboard不显示推送成功横条。弹窗和详情页提供细进度条。

Commit / Submit / Push失败时，弹窗只显示一处统一错误提示，注明失败仓库和分支；本地Commit保留，重试继续Push。macOS从Finder启动也会在用户`~/.local/bin`和Homebrew的`/opt/homebrew/bin`、`/usr/local/bin`查找Git LFS，供推送钩子、下载及同步使用，保留已有PATH优先级；无需重复安装已可运行的LFS。

未关联本地目录时，更改栏会明确提示并提供「关联本地目录」入口；远端提交图和文件树照常可用。已有SSH目录也可以匹配同一仓库的HTTPS账号，即使两种服务使用不同端口。

Dashboard仓库可分别平滑展开和收起分支；分支行与仓库行等高，保留相同的上下留白，系统减少动态效果时直接切换。

## Presence个人自动管理（0.30.0源码）

在「设置 → 插件 → Presence」登录账号归属服务，当前Git身份可访问的仓库和已关联工作区自动登记。可添加并选择多台明确信任此登录服务的Presence服务器，使用同一个个人身份；密码只交给归属服务。设置中没有个人仓库选择、团队选择或密码修改。

协作人员弹窗在姓名后显示实际设备名称，例如 `Taobe (Macbook Pro)`；同一人使用多台设备时在括号内列出设备名称。 人员卡片的每个分支下提供对应远程设备已授权的操作，点击进入现有预览和确认；离线设备不能执行。 这个入口已合入main并包含在0.31.0源码中，正式安装包仍等待公证完成。

[组织管理网页](https://git.freshli4.com:10443/presence/manage)独立维护组织、成员与具体仓库网址；绑定要求Presence组织owner和Git仓库ownership。成员访问匹配仓库时自动使用组织范围，Dashboard“托管组织”列/筛选、文件夹图标和详情显示组织与个人角色。同仓库可分别进入多个独立组织，不限制或合并。

同账号多设备支持Commit、Submit和两类abort，保留分支预览、说明编辑与备份；详情按服务器/组织隔离目标与结果。应用菜单“打开另一个实例”可使用独立账号数据目录。详情见[账号使用说明](docs/presence-accounts.md)及[公开协议](docs/presence-public-protocol.md)。客户端源码、NAS部署、正式三平台包和真实双设备操作分别验收；官网Docker分发、组织计费与开源许可证尚待交付。

仓库操作弹窗右上角的「−」可以收起到原操作按钮。准备或执行继续在后台进行；再次点击按钮可恢复草稿、勾选文件、进度和结果。收起期间可以切换页面，处理其他工作目录的任务；同一目录避免重复执行。后台完成或失败不会弹回占用页面。
