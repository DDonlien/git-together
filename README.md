# GitTogether

把仓库当作项目，把分支当作任务。

GitTogether 是一款面向 macOS 的独立 Git 工作台，把 GitHub、Gitea 和本地 Git 目录放在同一个视野里。它为同时推进多个项目、多个分支的开发者而设计：从仓库总览找到项目，在项目内看清分支、提交和文件，再按需接入本地更改。

## 一个项目，多条任务线

GitTogether 的核心视角是：仓库是项目，分支与 worktree（同一仓库的独立工作目录）是项目里的任务上下文。不同工作线围绕同一个仓库组织；浏览另一个分支，不等于检出它，也不会改动你正在工作的目录。

## 你可以用它做什么

### 汇集不同账号下的仓库

连接 GitHub 或自托管 Gitea，让可访问的仓库进入同一份 Dashboard。按账号、组织、仓库类型、本地关联状态和公开/私有可见性进行多选筛选，快速找到需要关注的项目；点击仓库的文件夹图标，即可展开实际远端分支。

### 不克隆，也能了解远端

没有本地目录，也可以浏览远端分支、提交关系和文件树。仓库工作台把分支图、更改与 Diff（文件差异）、文件树并排放置：选择一次提交，查看它改了哪些文件，同时在当前目录结构中辨认这些变化。

### 接入已有的本地工作

在桌面版中选择已有 Git 目录或项目父目录，自动匹配其中属于该仓库的真实工作目录。每个分支可以单独关联、解除；仓库入口保留「尚未关联 / 部分关联 / 完全关联」，未检出的分支不会自动创建目录。各 worktree 的未提交更改、文本 Diff 和本地文件树独立读取；远端文件可打开平台网页，本地文件可用系统默认应用打开。

### 让信息有序，给工作留出空间

Material 3 的亮暗主题与清晰的信息分区，让工作台保持统一：侧栏融入背景，内容卡片用色调区分层级。侧栏和三个内容栏都可以独立收起；调整布局时，当前选择、目录展开和任务草稿保持不变。

## 从哪里开始

1. 在设置中连接 GitHub 或 Gitea 账号。
2. 在 Dashboard 搜索仓库，展开分支，或点击仓库名称进入工作台。
3. 浏览远端提交和文件；需要查看本地更改时，再在桌面版关联已有目录。

仓库的可见范围始终取决于账号授权与平台权限。关联本地是可选步骤，不是读取远端内容的前提。

遇到读取或更新异常时，可在「设置 → 诊断日志 → 打开日志目录」找到本机记录。日志自动保留最近 24 小时，不上传，不记录令牌、密码、文件内容或明文仓库路径；空间上限 128 MB，超出后较早记录会被清理。此功能从 0.13.0 起提供，已有安装版需更新到包含此功能的版本。

## 当前状态

GitTogether 处于早期开发阶段，目前支持真实远端与多个已关联 worktree 的只读浏览。Dashboard 按顺序显示 Commit、Fetch、Pull、Push、Get Latest、Reconcile、Clear，用数字角标表达已有依据的同步、更改与读取错误；图标有悬停和按下反馈，暂时不显示悬停说明。Get Latest 定义为仅保留最新一层并清理旧历史以节省空间，Reconcile 以本地内容为准，Clear 以远端内容为准。这些 Git 操作尚未接入真实执行，入口仍禁用。AI 与在线协作仍在开发中。

目前提供源码和本地构建入口，尚未提供独立客户端的正式公开安装版。0.9.0起，已打包的桌面版提供「设置 → 应用更新」，从GitHub Releases检查、下载和重启安装；需要先发布对应安装包，源码推送本身不会触发更新。更新沿用账号及本地目录配置，不修改仓库文件。浏览器预览与桌面版的授权、目录选择支持有所不同，具体限制见[运行说明](docs/development.md)。

## 本地试用

列表行尾的隐藏图标可以隐藏仓库或分支；点击列表上方「已隐藏」可显示并逐项恢复，选择保存在本机。

在 macOS 上准备 Node.js、npm 和 Git，然后运行：

```bash
cd macos
npm install
npm run dev
```

浏览器预览位于 [127.0.0.1:4173](http://127.0.0.1:4173/)。保持开发服务运行，在另一个终端的 `macos/` 目录执行 `npm run desktop` 可打开桌面窗口。

GitHub 网页授权的首次开发配置、桌面打包与验证命令见[运行说明](docs/development.md)；应用配置由开发者准备，不是每位使用者的登录步骤。
