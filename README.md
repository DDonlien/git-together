# GitTogether

把仓库当作项目，把分支当作任务。

GitTogether 是一款面向 macOS 的独立 Git 工作台，把 GitHub、Gitea 和本地 Git 目录放在同一个视野里。它为同时推进多个项目、多个分支的开发者而设计：从仓库总览找到项目，在项目内看清分支、提交和文件，再按需接入本地更改。

## 一个项目，多条任务线

GitTogether 的核心视角是：仓库是项目，分支与 worktree（同一仓库的独立工作目录）是项目里的任务上下文。不同工作线围绕同一个仓库组织；浏览另一个分支，不等于检出它，也不会改动你正在工作的目录。

## 你可以用它做什么

### 汇集不同账号下的仓库

连接 GitHub 或自托管 Gitea，让可访问的仓库进入同一份 Dashboard。按账号、组织、仓库类型、本地关联状态和公开/私有可见性进行多选筛选，快速找到需要关注的项目；点击仓库的文件夹图标，即可展开实际远端分支。

### 不克隆，也能了解远端

没有本地目录，也可以浏览远端分支、提交关系和文件树。仓库工作台把分支图、更改与 Diff（文件差异）、文件树并排放置：选择一次提交，查看它改了哪些文件，同时在当前目录结构中辨认这些变化。

三栏之间的分隔条可左右拖动，以10%为一档调整空间，也支持键盘方向键。各栏仍可独立收起；重新展开会恢复当前工作台里调整过的比例。

### 接入已有的本地工作

在桌面版中选择已有 Git 目录或项目父目录，自动匹配其中属于该仓库的真实工作目录。每个分支可以单独关联、解除；仓库入口保留「尚未关联 / 部分关联 / 完全关联」，未检出的分支不会自动创建目录。各 worktree 的未提交更改和本地文件树独立读取。选择本地历史提交，可查看完整更改列表、文件状态和提交正文；取消后恢复工作区文件选择与提交草稿。更改列表不显示文件内容预览。远端文件可打开平台网页，本地文件可用系统默认应用打开。文件树底部显示分支和当前树提交号；本地目录紧随分支，点击可在系统文件浏览器中打开。

### 让信息有序，给工作留出空间

Material 3 的亮暗主题与清晰的信息分区，让工作台保持统一：侧栏融入背景，内容卡片用色调区分层级。侧栏和三个内容栏都可以独立收起；调整布局时，当前选择、目录展开和任务草稿保持不变。

## 从哪里开始

1. 在设置中连接 GitHub 或 Gitea 账号。
2. 在 Dashboard 搜索仓库，展开分支，或点击仓库名称进入工作台。
3. 浏览远端提交和文件；需要查看本地更改时，再在桌面版关联已有目录。
4. 本地未提交更改可填写Summary/Description后Commit，或通过Submit按当前分支生成AI说明，审阅文件清单后提交并推送；Commit后可单独Push选中的提交。圆形AI按钮仍可生成可编辑说明。

仓库的可见范围始终取决于账号授权与平台权限。关联本地是可选步骤，不是读取远端内容的前提。

遇到读取或更新异常时，可在「设置 → 日志 → 打开日志文件夹」找到本机记录，也可复制日志文件到剪贴板。日志自动保留最近 24 小时，不上传，不记录令牌、密码、文件内容或明文仓库路径；空间上限 128 MB，超出后较早记录会被清理。此功能从 0.13.0 起提供，已有安装版需更新到包含此功能的版本。

## 当前状态

当前源码0.21.2支持真实远端与多个已关联worktree的浏览，以及Commit / Submit / Push、Pull / Get Latest / Clean。Dashboard行内和仓库顶部统一为Pull / Get Latest、Commit / Submit、Push、Clean和隐藏五组；移除Reconcile及手动Fetch，图标使用手形指针，同组只显示一个正数角标。Dashboard数量表头居中对应按钮组；仓库行覆盖筛选出来的分支/目录，收起不缩小范围；仓库页顶部覆盖当前分支筛选，中栏只处理选中的更改上下文。Commit只创建本地提交；Submit使用本机Codex CLI配置的模型和登录，为每个分支预填可编辑的Summary和Description，确认后Commit再Push。关闭重开或筛选保留各分支草稿，生成不覆盖手工修改；Push失败保留Commit，重试不重复提交。Summary和Description使用官方Material Web描边字段，空态及正文按紧凑桌面统一为13px；顶部搜索按M3 Search bar规范组合。

Pull只快进合入，未提交文件或分叉历史会停止。Clean先展示按远端恢复、补齐和删除的具体文件（包含忽略的本地文件），确认后执行，保留本地提交和暂存区。Get Latest核验最新文件及LFS后替换为深度1的新目录，并实际删除可独立回收的旧历史与缓存；未推送提交、其他分支、标签或共享主目录会阻止清理，独立分支worktree可整理成单层目录，其他目录需要的共享历史保留并如实报告。后台每5分钟及变化触发实际Git fetch，不合并或改工作文件；保留已有数量、检查反馈、离线暂停及失败退避。未关联分支继续通过下载入口创建并关联目录。在线协作仍在开发中。

源码与后续更新包以`main`为基线，公开安装版在[GitHub Releases](https://github.com/DDonlien/git-together/releases)提供。桌面打包入口自动完成检查、签名、公证和正式更新发布；只推送源码不会发布安装包。已打包的桌面版提供「设置 → 应用更新」，检查、下载和重启安装。更新沿用账号及本地目录配置，不修改仓库文件。浏览器预览与桌面版的授权、目录选择支持有所不同，具体限制见[运行说明](docs/development.md)。

## 本地试用

列表行尾的隐藏图标可以隐藏仓库或分支；点击列表上方「已隐藏」可显示并逐项恢复，选择保存在本机。隐藏分支不参与「完全关联」判断，隐藏仓库不计入顶部仓库统计；所有本地分支都隐藏后，该仓库按未关联统计。查看隐藏项目时仍保持这些判断，恢复后重新计入；已保存的目录关联与文件保持不变。

尚未关联工作目录的分支只显示「下载」和「隐藏」。在桌面版点击下载，选择存放位置和新文件夹名称，完成后会自动关联真实worktree；已关联分支恢复原有Git操作。初次下载仅获取该分支最新一层；若有LFS文件，需要已安装Git LFS。已有同名文件夹不会被覆盖。

在 macOS 上准备 Node.js、npm 和 Git，然后运行：

```bash
cd macos
npm install
npm run dev
```

浏览器预览位于 [127.0.0.1:4173](http://127.0.0.1:4173/)。保持开发服务运行，在另一个终端的 `macos/` 目录执行 `npm run desktop` 可打开桌面窗口。

GitHub 网页授权的首次开发配置、桌面打包与验证命令见[运行说明](docs/development.md)；应用配置由开发者准备，不是每位使用者的登录步骤。桌面重新授权通过系统浏览器完成，复用应用安全存储；旧独立授权配置首次升级时自动安全迁移。

Summary与Description在中栏和提交弹窗中使用官方Material Web描边文本框，保留浮动标签和官方焦点样式。顶部搜索由官方填充字段与图标按钮按M3 Search bar规范组合，支持即时筛选、清空和Cmd/Ctrl+K；Material Web尚未提供独立Search bar组件。短窗口中提交字段独立滚动，底部操作保持可见。
