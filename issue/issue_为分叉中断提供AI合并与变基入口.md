# Description

Commit、Submit、Push、Pull 和 Get Latest 因本地与远端历史分叉而中断时，在对应位置提供 AI Merge / AI Rebase 整合入口。只在真实共同祖先和两侧独有提交得到证明时报告分叉，网络、权限及普通错误保留其原有原因；领先、落后、无共同祖先或截断历史不得误称分叉。保留触发操作和工作目录上下文。

AI Merge 允许选择本地目标或指定远端目标；远端目标须在本地安全整合、核验后由人明确确认推送。AI Rebase 允许选择远端分支和具体提交，展示将重放的本地独有提交及哈希改写、已发布历史风险。预览显示准确来源、目标、工作目录、远端、完整 SHA、共同祖先和 ahead/behind；远端或本地状态变化后拒绝过期预览。不得自动强推、丢弃工作文件或暂存、擅自改写已发布历史；明确结果及冲突中止/恢复，不承诺任意冲突可自动处理。

- [x] Pull 与 Get Latest 对真实分叉、仅领先及共同祖先未知给出不同提示；未改变 Git 写入行为。
- [x] Pull、Get Latest、Push 和 Submit 的已证实分叉提供 AI 合并或变基预览；保留触发上下文。Commit 本身只执行本地提交，源码中没有因分叉阻止 Commit 的弹窗。
- [x] 可选择本地或关联远端分支、指定远端完整提交，展示差异、重放提交、风险确认和状态；准备阶段可取消。
- [x] 支持隔离预览线性 AI Rebase、部分文本冲突处理及确认恢复；支持本地准备合并提交并经明确确认普通推送到指定远端分支。
- [ ] 验证五类入口、ahead/behind/diverged、脏工作区及暂存、冲突/取消/失败、远端并发、AI 不可用和 UI。Windows 真实环境单独标注。
- [ ] 用户界面验收。

已有 [AI 同步到最新](issue_提供可选择工作目录与来源分支的AI同步到最新操作.md) 的隔离准备与文本冲突处理路径被复用；本流程额外要求干净工作目录，并对远端、HEAD 和 Git 配置重新核验。
